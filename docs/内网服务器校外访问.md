# 用 Tailscale 从校外访问内网服务器

在已有权限的 Linux 服务器上，用 `tsnet` 把个人 SSH 入口接入自己的 Tailscale 网络。Mac 和服务器节点登录同一个 Tailscale 用户。服务器运行独立的用户级 `sshd`，只监听 `127.0.0.1:22222`。`tsnet` 在 tailnet 内监听 TCP 22，先用 `WhoIs` 核对连接设备的所属用户，再转发到个人 `sshd`。OpenSSH 继续核验登录账号和公钥。校园网入口和系统 SSH 配置可以继续使用。

准备一条已可信的服务器登录路径、可用的 Linux 用户级 systemd、OpenSSH 服务端和 Go。示例使用 `tailscale.com v1.104.1` 和 Go 1.27.1。服务器须能出站连接 Tailscale 控制面及中继。Mac 安装 Tailscale，并准备一把 SSH 密钥。

## 在服务器上配置个人 SSH

在当前普通用户的 Shell 中运行。目录用于独立部署，已存在同名文件时先确认内容。

```bash
umask 077
state="$HOME/.local/share/personal-ssh"
install -d -m 700 "$state" "$HOME/.config/systemd/user"
ssh-keygen -t ed25519 -N '' -f "$state/host_ed25519"
```

通过原有可信的登录路径，将 **Mac 的 SSH 公钥**保存为服务器上的 `$state/authorized_keys`，权限设为 600。私钥留在 Mac。接着生成独立配置：

```bash
cat > "$state/sshd_config" <<CONFIG
Port 22222
ListenAddress 127.0.0.1
HostKey "$state/host_ed25519"
PidFile "$state/sshd.pid"
AuthorizedKeysFile "$state/authorized_keys"
AllowUsers $(id -un)
AuthenticationMethods publickey
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
UsePAM no
StrictModes yes
AllowAgentForwarding no
X11Forwarding no
PermitTunnel no
Subsystem sftp internal-sftp
CONFIG
/usr/sbin/sshd -t -f "$state/sshd_config"
ssh-keygen -lf "$state/host_ed25519.pub"
```

记录最后一条命令显示的主机公钥指纹。Ubuntu 的 `sshd` 若报缺少 `/run/sshd` 等系统运行目录，由管理员补齐 OpenSSH 的运行依赖。若校验失败或个人账号被 OpenSSH 判定为锁定，先让管理员检查账号与系统服务配置。

## 编译并启动 tailnet 入口

在仓库根目录运行。设备名 `personal-gpu` 可改成自己 tailnet 内未占用的名称。

```bash
build=$(mktemp -d)
cp examples/personal-ssh/main.go "$build/"
(
  cd "$build" &&
  go mod init example.invalid/personal-ssh &&
  go get tailscale.com/tsnet@v1.104.1 &&
  go build -o "$state/personal-tailnet" .
)
```

把以下两个 unit 保存到当前用户的 `~/.config/systemd/user/`。

`personal-sshd.service`

```ini
[Unit]
Description=个人回环 SSH

[Service]
ExecStart=/usr/sbin/sshd -D -e -f %h/.local/share/personal-ssh/sshd_config
Restart=on-failure
RestartSec=5
UMask=0077
NoNewPrivileges=yes

[Install]
WantedBy=default.target
```

`personal-tailnet.service`

```ini
[Unit]
Description=个人 Tailscale SSH 入口
After=personal-sshd.service
Requires=personal-sshd.service

[Service]
ExecStart=%h/.local/share/personal-ssh/personal-tailnet -state %h/.local/share/personal-ssh/tailnet-state -hostname personal-gpu
Restart=on-failure
RestartSec=10
UMask=0077
NoNewPrivileges=yes

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now personal-sshd.service personal-tailnet.service
journalctl --user -u personal-tailnet.service -f
```

首次启动时，在自己的浏览器打开私有日志显示的认证链接，将该节点绑定到 Mac 使用的同一个 Tailscale 用户。保持为个人用户节点，以便程序核对所有者身份。若 tailnet 自定义了访问策略，还要允许该用户的 Mac 到该节点的 TCP 22。用 `loginctl show-user "$USER" -p Linger` 确认用户服务可退出登录后继续运行。需要时请管理员启用 Linger。

## 从 Mac 连接与排查

Mac 打开 Tailscale 后，用 `tailscale status` 确认节点在线。启用 MagicDNS 时可用设备名，也可从客户端复制完整域名。把以下示例写入 Mac 的 `~/.ssh/config`，替换设备名、Linux 登录账号和密钥路径。

```sshconfig
Host gpu-remote
    HostName personal-gpu
    Port 22
    User your-linux-user
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

```bash
ssh gpu-remote
sftp gpu-remote
```

首次连接时将提示中的主机指纹与服务器上通过可信路径取得的指纹核对。切换到手机热点后重试 SSH 和 SFTP，可验证校外网络可用。找不到主机名时先检查 Mac 的 Tailscale 状态与 MagicDNS。节点不在线时，在原有登录入口执行 `systemctl --user status personal-sshd.service personal-tailnet.service`，并检查私有日志。服务进程处于 active 时，仍需以客户端看到节点在线和实际 SSH 登录为准。若服务继承了用户级 Clash 代理环境，排查时也检查代理连通性。节点认证到期时，用当前私有日志中的链接重新绑定。

退役时运行 `systemctl --user disable --now personal-tailnet.service personal-sshd.service`，再从 Tailscale 管理控制台移除该个人节点。

以上流程改编自一次 Ubuntu GPU 服务器部署，原部署曾从校外验证交互式 SSH 和 SFTP 往返。参考 [Tailscale tsnet API](https://tailscale.com/docs/reference/tsnet-server-api) 与 [MagicDNS 文档](https://tailscale.com/docs/features/magicdns)。
